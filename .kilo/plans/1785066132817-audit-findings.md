# POS Application Audit — Additional Anomalies Found

## Overview
This document captures all anomalies discovered during a comprehensive audit of the `bjs-racing-pos` application, beyond the double stock update bug already fixed.

---

## HIGH PRIORITY

### 1. Stale product data after checkout
**File**: `src/pages/Pos.jsx:435-457`
**Issue**: `fetchProducts` depends on `[selectedCustomer, debouncedProductSearch, activeFilters]` — does NOT depend on `refreshTrigger`. After `processCheckout` → `resetPage()` → `forceRefresh()`, the product list is NOT re-fetched, showing stale stock values.
**Impact**: Cashier can add more items to cart than available stock. `handleAddToCart` checks `product.stok` from stale data → overselling possible.
**Fix**: Add `refreshTrigger` to `fetchProducts` dependency array and the `useEffect`.

### 2. No server-side stock validation on checkout
**File**: `src/pages/Pos.jsx:881-887` (`processCheckout`)
**Issue**: `processCheckout` inserts `stock_logs` without checking if products have sufficient stock. The trigger `handle_stock_log_change` will update `products.stok` even if it results in negative stock.
**Impact**: Selling more than available stock → negative stock levels.
**Fix**: Add a stock validation step before the `stock_logs` loop, or use a transactional RPC.

### 3. Held transactions restore stale product data
**File**: `src/pages/Pos.jsx:929-934` (`handleResumeTransaction`)
**Issue**: When resuming a held transaction, cart is restored from `heldTransaction.cart_data` which contains stale `stok`, `harga_jual`, `harga_beli` values from the time of holding. No refresh or re-validation.
**Impact**: Checkout with wrong prices or stock levels if products were updated while held.
**Fix**: Re-fetch product data on resume and update cart prices/stock.

### 4. `handleHoldTransaction` lacks submission guard
**File**: `src/pages/Pos.jsx:906-921`
**Issue**: No `isSubmitting` guard. Double-click creates duplicate held transactions.
**Impact**: Duplicate held transactions, wasted database rows.
**Fix**: Add guard check at the top of the function.

### 5. `total_terjual` inflated on transaction deletion
**Database**: `handle_stock_log_change` trigger
**Issue**: The trigger increments `total_terjual` by `ABS(NEW.perubahan)` only when `perubahan < 0` (sales). When a transaction is deleted, `delete_transaction_and_restore_stock` inserts a positive `perubahan`, so `total_terjual` is NOT decremented.
**Impact**: Sales reports show inflated total sold after deleted transactions.
**Fix**: Add a `total_terjual` adjustment in `delete_transaction_and_restore_stock` or in the trigger logic.

### 6. No transaction wrapper in `processCheckout` — partial failure risk
**File**: `src/pages/Pos.jsx:869-887`
**Issue**: Transaction insert and `stock_logs` inserts are separate Supabase calls. If transaction insert succeeds but `stock_logs` fails (or vice versa), data is inconsistent.
**Impact**: Transaction exists without stock deduction (or stock deducted without transaction).
**Fix**: Use a server-side RPC function with `BEGIN...COMMIT/ROLLBACK`, or delete the transaction if any stock_log fails.

## MEDIUM PRIORITY

### 7. Voice search can process multiple commands
**File**: `src/hooks/useVoiceSearch.js:22-42`, `src/components/AIAssistantModal.jsx:96-100`
**Issue**: SpeechRecognition with `interimResults: true` can fire `onresult` multiple times with different final transcripts. The `lastCommandRef` guard only prevents exact duplicates.
**Impact**: Same item added multiple times to cart if voice recognition produces similar-but-different transcripts.
**Fix**: Add debounce or a processing lock in the AI assistant.

### 8. Stock check in `handleCartChange` uses stale data
**File**: `src/pages/Pos.jsx:644-650` (`handleCartChange`)
**Issue**: When user manually changes quantity or clicks `+5` / `+10`, the `item.stok` comparison uses the stock value captured when the product was added to cart, not the current stock.
**Impact**: Cart quantity could exceed actual available stock if another transaction reduced it concurrently.
**Fix**: Re-validate stock from the server before checkout (see item #2).

### 9. `forceRefresh` only updates held transactions, not products
**File**: `src/pages/Pos.jsx:418`
**Issue**: `forceRefresh()` increments `refreshTrigger` which only triggers held transactions fetch (line 518). After stock changes, product list is not refreshed.
**Impact**: Stale data until manual page refresh.
**Fix**: Add `refreshTrigger` dependency to `fetchProducts` useEffect.

## LOW PRIORITY

### 10. React StrictMode double-render (development only)
**File**: `src/main.jsx:9`
**Issue**: `<React.StrictMode>` causes double execution of effects and renders in development. Not a production issue, but can cause confusion during testing.
**Impact**: Dev-only; effects run twice, state updates appear doubled.
**Recommendation**: Document this for developers.

### 11. No pagination on flash_sales query in store
**File**: `bjs-racing-store/src/pages/api/payment/create-transaction.ts:233-237`
**Issue**: Flash sales query doesn't use pagination (`!typedCartItems.length` items queried at once). Performance issue at scale.
**Impact**: Slow checkout with large flash sale catalog.

### 12. Missing `stok_dialokasikan` handling in trigger
**Database**: `handle_stock_log_change` trigger
**Issue**: The trigger updates `products.stok` and `total_terjual` but does not update `stok_dialokasikan` (allocated stock for wholesale). If `process_grosir_invoice` uses `stock_logs` for stock changes but also needs to track allocated stock separately.
**Impact**: `stok_dialokasikan` is managed separately and could become inconsistent.
**Fix**: Consider whether `stok_dialokasikan` should be handled by the trigger or application code.
